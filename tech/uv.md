# uv (resolver for the lock files)

## What it is

**uv** is a very fast Python package manager written in Rust. Here it is used for one job: its `uv pip compile` command reads the loose dependency rules in `pyproject.toml` and works out one complete, exact set of library versions that fit together, with a hash for every downloadable file. The result is written to a `.lock` file that plain `pip` can install.

## Why this repository uses it

Choosing compatible versions of dozens of libraries is a search problem (each library requires others, within ranges). A tool does it once, deterministically; the result is committed so every later install uses the same versions. uv is only needed by the person who changes dependencies (`make lock`), not by anyone who just runs the project.

## Where it appears

| File | What it does with this technology |
| --- | --- |
| `Makefile` | `make lock` runs `uv pip compile`. |
| `requirements*.lock (2 files)` | Their first two lines record the exact uv command. |
| `pyproject.toml` | The input. |


## How it works underneath

`uv pip compile` takes the requirement ranges, asks the package index (PyPI) which versions exist and what each requires, and runs a **resolver** (a backtracking search, using the PubGrub algorithm) until it finds one version of every library that satisfies all constraints. `--universal` produces a result that is valid for every operating system and Python version in range by adding *environment markers* (for example `; sys_platform == 'win32'`) where a dependency exists only on some platforms. `--generate-hashes` adds the SHA-256 of each file that may be installed (`sha-256.md`). `--python-version 3.12` resolves for the oldest supported Python, so the lock works on 3.12 and newer. `--extra dev` includes the optional group `dev` (the tools: ruff, mypy, pytest, ...). `-o FILE` names the output.

## Walkthrough of this repository's use

### The command in the Makefile

`Makefile`

```make
lock: ## regenerate requirements.lock and requirements-dev.lock (needs uv)
	uv pip compile pyproject.toml --universal --generate-hashes --python-version 3.12 -o requirements.lock
	uv pip compile pyproject.toml --universal --generate-hashes --python-version 3.12 --extra dev -o requirements-dev.lock
```

Each `uv pip compile pyproject.toml ...` line produces one file. The first writes `requirements.lock` (runtime libraries only). The second adds `--extra dev` and writes `requirements-dev.lock` (runtime plus tools). When the repository has a machine-learning extra, a third line produces `requirements-ml.lock` for one platform only (`--python-platform aarch64-apple-darwin` is macOS on Apple silicon), because PyTorch publishes different files for each platform.

### Its trace in the lock file

`requirements.lock`

```text
# This file was autogenerated by uv via the following command:
#    uv pip compile pyproject.toml --universal --generate-hashes --python-version 3.12 -o requirements.lock
```

The first two lines of every lock file are written by uv and record the exact command that produced it, so anyone can regenerate the file or see how it was made. The version of uv that wrote the files is not recorded; the uv on the machine used for these notes was 0.11.2.

## Try it yourself

1. `uv --version` prints the installed version (for example `uv 0.11.2`).
2. `make lock` regenerates the lock files (needs internet and uv) and `git diff --stat` shows what moved; when nothing was published since, there is no diff.
3. `uv pip compile pyproject.toml --universal --python-version 3.12 | head -20` prints a resolution without hashes to the terminal.
4. Install uv with `brew install uv` (macOS) or `pipx install uv`.

## Mistakes people make

- **Editing a lock file by hand.** Edit `pyproject.toml` and run `make lock`.
- **Locking on a different Python than the supported minimum**: `--python-version 3.12` guards against it.
- **Forgetting that a lock file is a snapshot**: new releases appear all the time; `pip-audit` (`pip-audit.md`) reports known problems with the pinned ones.
- **Committing only one of the lock files** after a dependency change.

## Check yourself

1. **What does `uv pip compile` produce?**  
   A fully pinned requirements file, with hashes if asked.
2. **What does `--universal` mean?**  
   The result is valid on all platforms, using environment markers where needed.
3. **Why is the ML lock made for one platform?**  
   PyTorch ships different files per platform, so no single universal resolution exists.
4. **Who needs uv?**  
   Only someone who changes the dependencies.
5. **Where is the command recorded?**  
   In the first lines of each lock file.
