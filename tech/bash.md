# Bash and the shell

## What it is

A **shell** is the program that reads the commands you type in a terminal and runs them. **Bash** is the most common one (macOS and Linux). A **shell script** is a text file of such commands. The language is small: you run programs, give them arguments, connect their outputs with pipes, and test whether they succeeded.

## Why this repository uses it

This repository runs shell commands in three places: inside the lines of the `Makefile`, in the CI workflow's steps (each is `make ...`), and in the one-line recipes. Java's wrapper script `java/mvnw` is also a shell script. Knowing the handful of shell ideas below is enough to read all of them.

## Where it appears

## How it works underneath

**Programs and arguments.** `ls -l src` runs the program `ls` with two arguments, `-l` and `src`. The shell splits the line at spaces, so quotes are used to keep text with spaces together: `"a b"` is one argument.

**Exit status.** Every program ends with a number: 0 means success, anything else means failure. `$?` holds the last one. `&&` runs the next command only after success; `||` only after failure; `;` always.

**Streams.** Every program has three channels: standard input (0), standard output (1), standard error (2). `>` sends output to a file, `2>&1` sends errors to wherever output goes, `|` connects the output of one program to the input of the next, and `/dev/null` is a file that throws everything away.

**Variables.** `NAME=value` (no spaces) sets one; `$NAME` or `${NAME}` reads it. `${NAME:-x}` reads it with a default. A variable put before a command (`A=1 cmd`) exists only for that command. `export` makes a variable visible to programs you start.

**Substitution.** `$(command)` is replaced by the command's output. `$((1+2))` is arithmetic.

**Processes.** `cmd &` runs in the background; `$!` is its process id; `kill PID` asks it to stop; `nohup` keeps it alive after the terminal closes.

**Tests.** `[ -f FILE ]` is true if the file exists; `[ -d DIR ]` for a folder; `[ -z "$X" ]` if the text is empty.

**Loops.** `for x in a b c; do ...; done`.

**Safety switches.** `set -e` (stop on error), `set -u` (error on unset variable), `set -o pipefail` (pipelines fail if any part fails).

## Walkthrough of this repository's use

### Shell commands inside the Makefile

The Makefile is covered line by line in `make.md`. These are the shell constructs in it that need the ideas above.

`Makefile`

```make
	@[ -f .env ] || { cp .env.example .env; echo "created .env from .env.example"; }
```

A test and a fallback in one line: `[ -f .env ]` is the program `[` (also called `test`) asked whether the file exists; its exit status is 0 for yes, 1 for no. `||` runs the right-hand side only when the left side failed (non-zero status). `{ a; b; }` runs several commands as a group. Single `;` separates commands. Double quotes keep the message together as one argument.

### `java/mvnw`

`java/mvnw` is generated by the Maven Wrapper plugin and is not edited here. It is a POSIX shell script (`#!/bin/sh`) that finds Java, reads `distributionUrl` from `.mvn/wrapper/maven-wrapper.properties`, works out the folder under `~/.m2/wrapper/dists/` where that Maven version lives, downloads and unpacks it there if it is missing, and then uses `exec` to replace itself by Maven's own `mvn` with the arguments you gave. `maven-wrapper-scripts.md` quotes and explains every line of it and of `mvnw.cmd`.

## Try it yourself

1. `echo $?` right after `ls` prints `0`; after `ls /nonexistent` it prints a non-zero number (macOS: `1`).
2. `true && echo yes; false && echo no; false || echo fallback` prints `yes` then `fallback`.
3. `X=hello; echo "$X ${Y:-default}"` prints `hello default`.
4. `echo "$(seq 1 3)"` prints the numbers 1 2 3, each on its own line.
5. `bash -c 'set -e; false; echo after'` prints nothing: `set -e` stopped at `false`. Without `set -e` it prints `after`.

## Mistakes people make

- **Spaces around `=`** in an assignment (`X = 1` runs a program called `X`).
- **Unquoted variables** that contain spaces: `rm $DIR` breaks if DIR has a space. Quote them: `rm "$DIR"`.
- **Ignoring failures.** Without `set -e` a script goes on after an error. The script here sets `set -euo pipefail`.
- **`cd` in a script that is later reused**: a `cd` changes the caller's folder if the script is `source`d. The subshell `( cd java && ... )` avoids it.
- **Killing by a broad pattern** (`pkill -f python`) on a shared machine: it kills other people's processes.

## Check yourself

1. **What does `a && b || c` do?**  
   Runs `b` if `a` succeeded; if `a` or `b` failed, runs `c`.
2. **What does `2>&1` mean?**  
   Send standard error (descriptor 2) to the same place as standard output (descriptor 1).
3. **What does `set -euo pipefail` change?**  
   Stop at the first failing command, treat unset variables as errors, and make a pipeline fail when any stage fails.
4. **What does `$!` hold?**  
   The process id of the most recently started background command.
5. **Why is `cd java && ./mvnw verify` written with `&&`?**  
   So that the build runs only if the `cd` worked, and in the right folder.
